## 2. 顺序核查（关键结论）

用 Mono.Cecil 扫描 `Stardew Valley.dll`（1.6.15）统计绘制入口：

| 事实 | 数据 |
|---|---|
| `SpriteText.drawString` 调用 | 59 处 / 30 个类型；`drawStringWithScroll*` 内部转调它 |
| `SpriteBatch.DrawString` 重载 | 全游戏只用 4 个（4参 string 94、9参 string 82、4参 StringBuilder 12、9参 StringBuilder 5） |
| HUD toast | `Utility.drawTextWithShadow`（SpriteFont） |
| 电视 | `Game1.drawObjectDialogue` → DialogueBox（**已覆盖**） |
| 任务日志正文 | `SpriteFont`（`drawTextWithShadow`），**不是**像素字体 |
| 信件正文 | `SpriteText.drawString`（`width=menu.width-64`, `drawBGScroll=-1`） |

**结论**：原计划「按 API 分阶段（SpriteText → SpriteFont）」不高效——`QuestLog`/`ShopMenu`/`JunimoNote`/`LetterViewerMenu` 同一菜单混用两种 API，按 API 切会重复实现；HUD/电视归属也写错。
改为 **按文本面切片**（价值 × 风险）：阶段 0 基础设施 → 1 信件 → 2 任务日志/订单板 → 3 菜单长尾 → 4 世界层 → 5 交互。
已写入 `docs/planning/开发计划与节点控制.md` §8 与 `docs/ai/DECISIONS.md` 决策 15。

### 对齐问题的定量证据

- 用户实机截图 + 同会话 `[诊断]` 日志（`QuestLog`，`dialogueFont`，`Spacing=-2`，`lineSpacing=42`，`space=15`）。
- 校准：屏幕坐标 = UI 坐标 − 230（1:1）。
- 修复前逐词误差：`If 0 / you +4 / want +4 / to +8 / become +12 / a +16 / farmer, +20 / 行尾 you +24`——**每词 +4px**。
- 根因：MonoGame `MeasureString` 对每个字符都累加 `Spacing` 与左右边距；「词宽 + 空格宽」分段累加时每个词边界少计 `2×Spacing`（−2 → 4px）。
- 修复后理论误差恒定为 −3px（字形 left side bearing），不再累积。
